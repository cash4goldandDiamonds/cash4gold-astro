# CMS release review binding

Independent final review reproduced two risks: a page retained its old approval after an edit, and a reviewer reference did not have to resolve to a real document. These are now addressed at the production website build gate. Saving or publishing a Sanity document is still distinct from authorizing a website release.

Production CMS pages must resolve their reviewer to a named, published document. A second release gate requires `CMS_RELEASE_REVIEW` to match SHA-256 fingerprints of the tracked rendering source and the actual projected pages, shared business/navigation/social settings, resolved redirects and public tracking/verification settings. A changed FAQ answer, preserved repository layout, image, title, shared navigation, redirect or tracking configuration invalidates the old release record. This is an operational approval record controlled by the build administrators, not a digital signature or a replacement for account permissions.

Once all page reviews and source prerequisites pass, an attempted production CMS build writes `.cache/cms-release-candidate.json`. It contains hashes and identifiers only, with `approved: false` and empty reviewer/date fields. The build stops unless an independently reviewed matching record is supplied. Do not automatically turn this candidate into approval. An authorized human must compare the exact release, record their identity and actual review time, and separately approve launch. The `.cache` file stays outside Git. No approval was fabricated or applied in this task.

Private CMS preview supports an explicit `SANITY_PERSPECTIVE=published` or `drafts`, always against the verified private `migration-staging` dataset. Outputs are separated under `.cache/cms-preview/published` and `.cache/cms-preview/drafts`; neither overwrites `dist`. Both enforce noindex, disable analytics, scan output for the session credential, and compare all CMS document revisions before and after building. The helper never deploys or publishes. A current read credential and account connectivity are still required to execute this acceptance check.

The hosted Studio was verified to open through Cloudflare Access and read the private page list and gold editor. The hosted gold CMS document still contains older metadata/layout. Reconcile a fresh raw export with the reviewed GitHub implementation and existing proposal files before selecting CMS content for any website build. Preserve existing drafts; do not import over them blindly.

Still unverified: an actual current draft rendered through the private preview helper, a human publishing a reconciled change, a controlled rebuild of that change, and restoration of the previous release. There is no automatic publish webhook configured. Production publishing remains blocked and the live WordPress site is unchanged.
